# J.A.R.V.I.S 2.0

A mobile-first personal AI assistant starter. The first milestone is a working Expo mobile interface connected to a Node.js API and Groq, with optional Hugging Face fallback.

## Project layout

- `app/` — Expo React Native application
- `server/` — Express API; provider keys stay on the server
- `.devcontainer/` — GitHub Codespaces configuration
- `docs/ROADMAP.md` — implementation plan and module status

## Development in GitHub Codespaces

1. Open this repository in GitHub Codespaces.
2. If your Codespace predates the devcontainer setup, run **Codespaces: Rebuild Container** from the Command Palette.
3. Open a terminal. Dependencies are installed by the devcontainer; if not, run `npm run install:all`.
4. Add your provider key as a Codespaces secret or create `server/.env` in the Codespace. Never commit `.env`.
5. Start the API with `npm run start:api`.
6. In the Codespaces **Ports** panel, make port `8787` private unless you intentionally need public access. Open its forwarded URL and append `/api/health` to test it.
7. Set `EXPO_PUBLIC_API_URL` in `app/.env` to the forwarded API URL, for example `https://YOUR-CODESPACE-8787.app.github.dev`. Do not add a trailing slash.
8. Start Expo with `npm run start:app`. Use the Expo Go-compatible link/QR generated by Expo. If the iPhone cannot open the forwarded API, check the port visibility and URL.
9. Restart Expo after changing environment variables.

## Local laptop development

- Backend: `cd server && npm install`, create `.env` from `.env.example`, then `npm run dev`.
- App: `cd app && npm install`, set `EXPO_PUBLIC_API_URL` to the laptop's LAN IP and port 8787, then `npx expo start --tunnel`.
- The iPhone and laptop should be on a compatible network. On a physical iPhone, `localhost` means the phone itself, not the laptop.

## AI provider configuration

Groq is the primary provider. Hugging Face is an optional fallback if `HF_TOKEN` is configured. Both secrets belong only in the server environment. The mobile app must never contain provider keys.

Use newly generated credentials. Revoke any credential previously pasted into a chat or committed to a repository.

## Security and deployment status

This repository is public. Do not store secrets, personal records, financial account data, or production customer data here. The starter API is for development, not a production multi-user service: before public deployment, add user authentication, authorization, rate limiting, abuse controls, secure logging, and persistent storage. Keep the API port private while testing.

## Implemented now

- Dark JARVIS-themed mobile dashboard
- Text chat screen
- Express health endpoint
- Groq chat integration
- Optional Hugging Face-compatible fallback
- Codespaces workspace configuration

## Not implemented yet

Voice input/output, authentication, database and chat history, reminders/notifications, live web research, image generation, business integrations, finance data integrations, and analytics are planned modules. See `docs/ROADMAP.md`.
